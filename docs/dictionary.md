## 判定のしくみ

1件の文は、次の順に処理します。

1. **逆接で分ける**: 文に `splitters`（けど・のに など）があれば、最初に見つかった逆接の後ろだけで判定します。
   前の語は「数えなかった語」（理由: 逆接）になります。
2. **語を探す**: `words` の語を、長い語から順に探します。
   * 長い語の内側にある短い語は数えません（最長一致）。
   * `wordExclusions` の複合語の内側にある語は数えません（「精神」の中の「神」）。
   * 同じ語は、最初の1か所だけを数えます。
3. **語ごとに点数を決める**（見つかった順）:
   1. **用法**: `followedBy` にある語は、直後の文字が合わなければ数えません。
   2. **条件・説明**: 語の後ろ（句読点まで、最大 `hypotheticalWindow` 文字）に `conditionMarkers` か `descriptionMarkers` があれば数えません。
   3. **極性**: `wordPolarity` に語があればその値、なければカテゴリの `polarity` の値を使います。
   4. **否定**: 語の後ろの否定ウィンドウに `negations` があれば、符号を反転します（詳しくは下の「否定の範囲」）。
   5. **強調**: 語の前の6文字に `intensifiers` の語があれば、その倍率を掛けます。
4. **判定する**: 判定スコア（合計 ÷ √ヒット数）が `threshold` 以上ならポジティブ、−`threshold` 以下ならネガティブ、その間は中立です。
   ヒットが0なら「判定できません」です。極性が 0 の語は根拠に表示しますが、ヒットに数えません。

### 否定の範囲

否定を探す範囲（否定ウィンドウ）は、次のように決めます。

1. 語の後ろから始めます。
2. `negationBoundaries`（て・で・、・。など）の**最も近いもの**で切ります。
   ただし、その位置が `negationBridges`（ではな・ていな など）で始まるときは切りません（「好きではない」）。
3. 長さを `negationWindow`（8文字）までにします。語ごとに `negationWindowOverrides` で広げられます。
4. 後ろに別の辞書の語があれば、そこで切ります。否定は最も近い語に効きます
   （「かゆみが全然治まらない」の「ない」は「治ま」だけを否定し、「かゆみ」には及びません）。

範囲の中で次を調べます。

* `negationExceptions`（たまらない・仕方ない など）があれば、否定と見なしません。
* `relievers`（消え・和ら など）があり、語の極性がマイナスなら、極性をプラスに反転して 0.7 倍にします（「かゆみが消えた」の「かゆみ」は −0.6 → +0.42）。

## 全項目の一覧

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `groups` | カテゴリのまとまり → カテゴリの配列 | カテゴリの分類。`レビュー観点` のカテゴリが画面の「観点別」、それ以外が「感情・評価」に表示される |
| `polarity` | カテゴリ → 数値 | カテゴリの極性。`wordPolarity` がない語に使う |
| `words` | カテゴリ → 語の配列 | 辞書の語（語幹で登録する） |
| `wordPolarity` | 語 → 数値 | 語ごとの極性。カテゴリの極性より優先する |
| `negatedPolarity` | 語 → 数値 | 否定されたときだけ数える語と、そのときの極性（[下で説明](#否定されたときだけ数える語negatedpolarity)） |
| `negations` | 文字列の配列 | 否定の語（ない・なく・なかった・ません・ぬ・ず） |
| `negationExceptions` | 文字列の配列 | 「ない」を含むが否定ではない表現（たまらない・仕方ない・しかない など） |
| `negationBoundaries` | 文字列の配列 | 否定の範囲を切る文字（て・で・、・。・,・.） |
| `negationBridges` | 文字列の配列 | 境界があっても否定の範囲を切らない表現（ではな・ていな など） |
| `negationWindow` | 数値 | 否定を探す範囲の文字数（8） |
| `negationWindowOverrides` | 語 → 数値 | 語ごとの否定の範囲（「二度と」: 14 など） |
| `relievers` | 文字列の配列 | マイナスの語の後ろにあると、良くなったことを表す語（溶け・消え・取れ・和ら・癒え・軽く） |
| `splitters` | 文字列の配列 | 逆接の語（のに・けど・しかし・にも関わらず・にもかかわらず）。リストの順に探す |
| `conditionMarkers` | 文字列の配列 | 条件の目印（場合は・ないときは など） |
| `descriptionMarkers` | 文字列の配列 | 対象の説明の目印（ための・向けの など） |
| `hypotheticalWindow` | 数値 | 条件・説明の目印を探す文字数（12） |
| `hypotheticalBoundaries` | 文字列の配列 | 条件・説明の目印を探す範囲の終わり（、・。・,・.）。句読点そのものも範囲に含める |
| `followedBy` | 語 → 文字列の配列 | 直後がこの文字のときだけ数える語（[下で説明](#用法で数えるかを決める語followedby)） |
| `wordExclusions` | 語 → 複合語の配列 | この複合語の内側にあるときは数えない（「神」→「精神」「神経」） |
| `intensifiers` | 語 → 倍率 | 強調の語と倍率（とても: 1.5、めっちゃ: 2 など） |
| `threshold` | 数値 | 判定のしきい値（0.5） |
| `boundaryCheckMaxLength` | 数値 | 形態素解析を使うとき、この文字数以下の語は形態素の先頭からしか一致しない（2） |

## よくある編集

### 語を追加する

`words` のカテゴリに、語幹で追加します。

```json
"words": {
  "喜び": ["嬉し", "最高", "神すぎる"]
}
```

### 観点の語を追加する

観点（味・品質・サービス・価格・使いやすさ・配送・総合・結果・体の反応）は、
同じカテゴリにほめ言葉と不満が混ざるため、カテゴリの極性を `0` にしています。
観点の語は、**必ず `wordPolarity` に極性を書きます**（書かないと極性 0 になり、判定に使われません）。

```json
"words":        { "味": ["美味し", "不味"] },
"wordPolarity": { "美味し": 1, "不味": -1 }
```

否定が語の一部になっている表現（「二度と行かない」「うまくいかず」）は、否定を含めた形で登録します（`"二度と行かな"`）。
否定を含めないで登録すると、後ろの否定で極性が反転してしまいます。

### 誤ったヒットを防ぐ

短い語が別の語の一部としてヒットするとき（「精神」の中の「神」）は、`wordExclusions` に複合語を追加します。

```json
"wordExclusions": {
  "神": ["精神", "神経", "神社"],
  "最低": ["最低限", "最低気温", "最低賃金"]
}
```

辞書にある長い語の中の短い語は、最長一致で自動的に数えません。

### 否定の語・強調の語を追加する

```json
"negations": ["ない", "なく", "なかった", "ません", "ぬ", "ず"],
"intensifiers": { "超": 2, "かなり": 1.3 }
```

## 特別なルールの語

### 否定されたときだけ数える語（`negatedPolarity`）

「眠れる」「効く」「動く」のように、**できて当たり前の結果**を表す動詞は、
肯定の形（眠れた）ではほめ言葉にならず、否定の形（眠れなかった）だけが不満になります。
こうした語は `negatedPolarity` に**否定されたときの極性**を登録します。

```json
"words":           { "結果": ["眠れ", "効か", "動か"] },
"negatedPolarity": { "眠れ": -0.8, "効か": -0.8, "動か": -0.8 }
```

* 否定されたとき（眠れなかった・効かず）だけ、その極性で数えます（強調も効きます）。
* 肯定の形（眠れた・効く・動かす）は**ヒットに数えない**ので、ほかの語の点数を薄めません。
* 肯定の形でもほめ言葉になる語（役に立つ）は、通常の `wordPolarity` に登録します。
* 語は、否定が続く形（未然形・可能形）で登録します: 「効か」「眠れ」「つながら」。
* 「〜しか…ない」「いつまで経っても…ない」「二度と…ない」「まともに…ない」のように、
  否定が句の一部になっている表現もここに登録します。否定が節の終わりに来て8文字を超える場合は、
  `negationWindowOverrides` で範囲を広げます（「二度と**あの店には行か**ない」）。

### 条件・説明の中の語（`conditionMarkers` / `descriptionMarkers`）

「動かない場合は〜」「壊れた場合は〜」のような**条件**や、
「眠れない夜のための〜」「疲れやすい人向けの〜」のような**対象の説明**は、書き手の体験や評価ではありません。
語の後ろ（句読点まで、`hypotheticalWindow` 文字以内）に目印があれば、否定の有無にかかわらず、その語を数えません。

```json
"conditionMarkers":   ["場合は", "場合には", "場合、", "場合でも", "場合があります", "場合がございます", "かどうか", "ないときは", "ない時は", "ないときには", "ない時には"],
"descriptionMarkers": ["ための", "向けの", "向けに", "に悩む", "にお悩み", "でお困り"],
"hypotheticalWindow": 12
```

* 数えなかった語は結果の `skippedWords` に入り、画面にも理由つきで表示されます。
* 「〜たときは」（壊れたときは困った）は過去の出来事なので、目印にしていません。
* 「〜たら」（使ったら壊れた）は「〜して、その後」の意味が多いので、目印にしていません。
* 「ため」（雨のため中止）は理由なので、「ための」だけを目印にしています。
* 「使えないアプリ」のように名詞を修飾する形は不満を表すので、目印がなければ数えます。
* 目印は**句読点まで**（句読点を含む）を見ます。否定の範囲と違い、「て」「で」では切りません
  （「壊れていた場合、」「使えない場合でも」を見つけるため）。

「場合」は、後ろの助詞で意味を区別します。

| 表現 | 意味 | 扱い |
| --- | --- | --- |
| 場合は／場合には／場合、／場合でも | 条件 | 数えない |
| 場合が多い／場合がある／場合もある | 頻度（〜することがある） | **数える**（「起動しない場合が多い」は不満） |
| 場合があります／場合がございます | 丁寧な注意書き | 数えない |
| 〜かどうか | 間接疑問（使えるかどうか調べている） | 数えない |

### 用法で数えるかを決める語（`followedBy`）

「よく」は「良く」（よくない・よくなった・よくて）のほか、
副詞として「頻繁に」（よく壊れる）「十分に」（よく動く）「とても」（よく似た）の意味があります。
`followedBy` に、**直後に続くときだけ数える文字**を登録します。

```json
"followedBy": { "よく": ["な", "て"] }
```

* 直後が合わないときは数えず、`skippedWords` に `reason: "usage"` で入ります（画面では「用法」）。
* 「ちょうどよく」「ほどよく」「気持ちよく」「心地よく」は、複合語として別に登録しています。
* 漢字の「良く」には適用しません。

## 形態素解析を使うときの違い

[kuromoji.js](https://github.com/takuyaa/kuromoji.js)（Apache-2.0、辞書は IPADIC）で文を形態素に分けると、次の2点が変わります。

| 用途 | 文字列モード | 形態素解析あり |
| --- | --- | --- |
| 否定 | 範囲の中に「ない」「ず」などの文字列があるか | 範囲の中に**否定の形態素**（助動詞 ない・ぬ・ん、形容詞 ない）があるか。「少ない」の「ない」や「必ず」の「ず」は数えない |
| 語の区切り | 部分一致（「精神」の中の「神」は `wordExclusions` で防ぐ） | `boundaryCheckMaxLength`（2文字）以下の語は、形態素の先頭からしか一致しない。長い語は「お気に入り」の「気に入」のように複合語の中でも一致する |

* **ブラウザ**: 既定はオフで、kuromoji は一切ダウンロードしません。画面の「詳細設定」でオンにしたときだけ、
  kuromoji 本体（バージョン固定 + SRI）と辞書（約18MB、12ファイル）を `data/kuromoji-dict.json` の URL から読み込みます。
  * 既定をオフにした理由: いまの辞書では精度が上がらない（[評価](evaluation.md#形態素解析の効果)）のに、約18MB のダウンロードが必要なため。
* **Node.js（テスト・評価）**: `npm ci` で kuromoji をインストールし、既定でオンにして評価します。
  `--no-morphology` で文字列モード（ブラウザの既定）と比べられます。
* **擬似API** は、1回ごとに約18MB を読み込まないよう、文字列モードのままです。
* **改ざんの検知**: kuromoji 本体は読み込むときに SRI で確かめます。辞書は XHR で読むため SRI を付けられないので、
  CI の `check:cdn` が本体・辞書とも `data/kuromoji-dict.json` のハッシュと照合します。

## 語彙の追加手順（ゲート）

テストセットの誤判定から語を拾うと、そのテストセットに合わせた調整になってしまいます。
語は、**レビューの観点 × 表現の種類**で一般的なものを書き出し、次の確認（ゲート）を通したものだけを追加します。

1. 既存の語と重複・部分一致しないか（最長一致で解決できるか）。重複はテストでも検出します。
2. 開発用セットの**中立の文に、新しくヒットする語がない**。
3. 開発用セットで**新しい誤判定がない**。
4. 開発用セットで**逆の極性に動いた文がない**（誤りが、より悪い誤りに変わったのを見逃さないため）。
5. ホールドアウトを書いた**後**に思いついた語は入れない（そのホールドアウトが開発用セットに移ってから追加する）。

ゲート 2〜4 は次のコマンドで確かめます。

```bash
npm run gates
```

直前のコミットの辞書と作業中の辞書を、開発用セットだけで、形態素解析あり（Node の既定）と文字列モード（ブラウザの既定）の両方で比べます。
1件でも当てはまれば失敗します。

辞書を変えたら、評価とベースラインの更新も行います（[CONTRIBUTING.md](../CONTRIBUTING.md#辞書を改善したとき)）。
